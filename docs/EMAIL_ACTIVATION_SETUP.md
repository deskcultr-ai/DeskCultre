# Deskcultr Email Activation Setup

The app is wired to send Supabase Auth confirmation emails and return users to:

```text
/auth/callback?next=/onboarding
```

After the activation link is clicked, the user lands on onboarding where they can
create a new organization or join an existing one through the existing RPC flow.

## Supabase Auth Settings

In Supabase Dashboard, open:

```text
Authentication -> URL Configuration
```

Set:

```text
Site URL:
https://deskculture.deskcultr.workers.dev
```

Add these redirect URLs:

```text
https://deskculture.deskcultr.workers.dev/auth/callback
https://deskculture.deskcultr.workers.dev/auth/callback?next=/onboarding
http://localhost:3000/auth/callback
http://localhost:3000/auth/callback?next=/onboarding
```

## Enable Email Confirmation

Open:

```text
Authentication -> Providers -> Email
```

Set:

```text
Confirm email: Enabled
```

## Sender Name

Open:

```text
Project Settings -> Authentication -> SMTP Settings
```

Use your SMTP provider and set the sender display name to:

```text
Deskcultr
```

Use a verified sender email from your domain, for example:

```text
no-reply@deskcultr.com
```

Supabase does not allow branded template edits on free-tier projects that use
the default email provider. If the dashboard blocks the template save or CLI
push, configure a custom SMTP provider first, then apply the template below.

## Email Template

Open:

```text
Authentication -> Email Templates -> Confirm signup
```

Subject:

```text
   Welcome to Deskcultr - activate your account
```

Template source is stored locally at:

```text
supabase/templates/confirmation.html
```

The important link variable is:

```html
{{ .ConfirmationURL }}
```

That link is generated by Supabase and includes the redirect URL supplied by the
app during signup.

## App Flow

1. User registers in Deskcultr.
2. App calls `supabase.auth.signUp`.
3. Supabase sends the Deskcultr activation email.
4. User clicks the activation link.
5. Supabase redirects to `/auth/callback?next=/onboarding`.
6. The app exchanges the auth code for a session.
7. User lands on onboarding.
8. User creates an organization with `create_company` or joins one with
   `join_company_for_testing`.

## Admin User Invites

The Users & Teams page creates one-time invite records with:

```text
create_user_invite
redeem_user_invite
get_admin_users_data
```

For real outbound invite email from Cloudflare, configure these Worker
variables/secrets:

```text
RESEND_API_KEY
INVITE_FROM_EMAIL=Deskcultr <no-reply@your-domain.com>
NEXT_PUBLIC_APP_URL=https://deskculture.deskcultr.workers.dev
```

Without `RESEND_API_KEY`, the invite is still created and the admin can see the
redeem code/link in the modal, but the Worker cannot send the email.
